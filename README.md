# AqroTrain —— 视觉标注训练平台（对标阿丘科技 AIDI）

基于 **Visual Studio 2022 (v143) + Qt 5.12.10 + OpenCV 4.6.0** 的图像标注与训练软件，
界面与工作流对标**阿丘科技 AIDI**，支持 **图像分类 / 目标检测 / 图像分割** 三类模块。

工程使用 VS 可直接打开：双击 `AqroTrain.sln` 即可。

---

## 一、与 AIDI 的对应关系

| AIDI 概念 | 本工程实现 |
| --- | --- |
| **工程** | 一个目录，含 `project.json` 与工程级图像池 |
| **模块** | 工程内的分类 / 检测 / 分割模块，可串联多个；顶部「模块链」显示 |
| **删除模块** | **连同其后所有模块**的数据、模型、测试结果一起删除（与 AIDI 一致） |
| **工程图片格式** | 新建工程时选择 PNG / BMP / TIFF / JPEG，导入图像按该格式统一转码 |
| **导入数据** | 图像复制进工程 `images/`，重名自动加序号；支持导入文件夹 |
| **数据划分** | 每张图在每个模块下有三态：未划分 / 训练集 / 测试集；支持 CTRL / SHIFT / CTRL+A 多选后右键 |
| **OK 图** | 无缺陷正例，可对单张或多张设置；用于训练与过检率统计 |
| **标注** | 分类=点选类别；检测=矩形 / 固定尺寸框；分割=画笔 / 橡皮 / 多边形 / 矩形 |
| **智能标注（预标注）** | 用已训练模型对未标注图像自动标注，标记为「预」，人工复核后确认 |
| **训练 / 测试参数** | 左侧可收起的两个区块，参数改动即时写回模块 |
| **训练测试** | 训练完成**自动在测试集上评价**，刷新指标面板 |
| **结果验证** | 显示类型切换「原图 / 标注 / 测试结果」；精确率、召回率、**漏检率、过检率** |
| **导出模型** | 模型主文件 + 元数据一起导出，可在「模型测试」里重新加载验证 |

### 8 步工作流

```
新建工程 → 添加模块 → 导入数据 → 标注数据 → 数据划分 → 设置参数 → 训练测试 → 结果验证 → 导出模型
```

## 三、环境配置

### 本机实测可用环境

| 组件 | 版本 / 位置 |
| --- | --- |
| Visual Studio 2022 Community | `D:\Program Files\Microsoft Visual Studio\2022\Community`（MSVC 14.38，v143） |
| Windows SDK | `10.0.22621.0`（`D:\Windows Kits`） |
| Qt | `5.12.10 msvc2017_64`（`D:\softInstall\Qt5.12.10\5.12.10\msvc2017_64`） |
| Qt VS Tools | 已安装，注册名 **`5.12.10_msvc2017_64`** |
| OpenCV | `4.6.0`（`F:\opencv\build`，库在 `x64\vc15`） |

> OpenCV 的 `vc15` 库与 VS2022 的 `v143` **二进制兼容**，可直接使用。

### 1. 注册 Qt 版本（Qt VS Tools）

VS2022 → 扩展 → **Qt VS Tools → Qt Versions**，确认存在：

- **Name**：`5.12.10_msvc2017_64` ← 必须与工程中 `<QtInstall>` 完全一致
- **Path**：`D:\softInstall\Qt5.12.10\5.12.10\msvc2017_64`

若你注册的名称不同，修改 `AqroTrain.vcxproj` 中两处 `<QtInstall>` 的值即可。

### 2. 配置 OpenCV

打开 `AqroTrain/props/OpenCV.props`，按需修改：

```xml
<OpenCV_DIR Condition="'$(OpenCV_DIR)'==''">F:\opencv\build</OpenCV_DIR>
<OpenCV_VER Condition="'$(OpenCV_VER)'==''">460</OpenCV_VER>
<OpenCV_VC  Condition="'$(OpenCV_VC)'==''">vc15</OpenCV_VC>
```

编译后会自动把 `opencv_world460*.dll` 复制到输出目录。

### 3.（可选）启用 LibTorch 深度学习后端

程序**默认不使用** LibTorch，此时可正常编译并运行 OpenCV 轻量后端。

1. 从 <https://pytorch.org/get-started/locally/> 下载 **LibTorch**
   （`LibTorch` → `Windows` → `Release` → `C++/Java` → CPU 或 CUDA），解压，例如 `D:\libtorch`；
2. 确认 `D:\libtorch\include\torch\script.h` 与 `D:\libtorch\lib\torch.lib` 存在；
3. 设置环境变量后**重新编译**：

   ```powershell
   setx LIBTORCH_DIR D:\libtorch      # 设置后需重开终端 / VS
   ```

   或在 MSBuild 命令行传入：

   ```powershell
   msbuild AqroTrain.sln /p:Configuration=Release /p:Platform=x64 /p:LibTorch_DIR=D:\libtorch
   ```

`props\LibTorch.props` 会自动探测：只有确实找到 `include\torch\script.h` 时才定义宏
`AQROTRAIN_ENABLE_LIBTORCH` 并链接 `torch.lib;torch_cpu.lib;c10.lib`，
否则保持关闭，工程仍然正常编译。程序运行时也可通过
**帮助 → 训练后端信息** 查看当前后端状态。

## 五、使用流程

### 1. 新建工程

**文件 → 新建工程**：填名称、选保存位置、选**工程图片格式**。
程序会创建 `project.json`、`images/`、`thumbs/`、`modules/`。

> 缺陷检测建议选 **PNG**（无损，不会引入压缩伪影）。

### 2. 添加模块

点模块条的 **「＋ 添加模块」**：选类型（分类 / 检测 / 分割）并命名。
一个工程可以有多个模块，它们共享同一个图像池，但**各自持有独立标注**。

### 3. 导入图像

**文件 → 导入图像 / 导入文件夹**。图像会被复制进 `images/` 并按工程格式统一转码。

### 4. 标注

> **画布上方有一条引导提示栏**，会随模块类型与当前状态告诉你下一步该做什么
> （缺少类别、没有图像、当前类型的正确标法等）。卡住时先看它。

| 模块类型 | 操作方式 |
| --- | --- |
| **图像分类** | **整张图对应一个类别，不需要涂抹**：在右侧「标签类别」点选类别，**点一下立即保存并跳到下一张未标注的图** |
| **目标检测** | 「矩形」拖拽画框，或「固定尺寸框」点一下放置固定大小的框；「选择」工具可点选、拖动、拖四角缩放；`Delete` 删除 |
| **图像分割** | 「画笔」涂抹、「橡皮擦」擦除、「多边形」围区域（双击 / 右键 / 回车闭合、Esc 取消）、「矩形」填充 |

> **⚠ 检测 / 分割模块的索引 0 是「背景」**，用它作画或画框不会产生有效目标。
> 程序会自动默认选中第一个目标类别；若停在背景类，画笔光标会显示为**红色虚线**，
> 状态栏与提示栏也会说明，操作会被拦截并给出提示。

**对象级编辑（本工程的核心能力）**

标注的**真源是可编辑的对象列表**，分割掩码由对象列表光栅化得到。因此：

- 选中对象后可**整体拖动**；矩形可**拖四角缩放**；多边形可**拖顶点**；
- 多边形：**双击边插入顶点**、**右键顶点删除顶点**（至少保留 3 个）；
- 对象列表里可以**改类别 / 删除 / 复制**；`Ctrl+C` / `Ctrl+V` 可**跨图复用**对象；
- 撤销 / 重做（`Ctrl+Z` / `Ctrl+Y`）对几何、增删、改类别一律有效。

常用快捷键：

| 快捷键 | 功能 |
| --- | --- |
| `V` / `B` / `E` / `G` / `R` / `F` / `H` | 选择 / 画笔 / 橡皮 / 多边形 / 矩形 / 固定框 / 平移 |
| `1` … `9` | 快速切换类别（在画布上按，不会抢走输入框的数字） |
| `A` / `D` | 减小 / 增大笔刷 |
| `Ctrl+滚轮` | 调整笔刷大小 |
| `滚轮` | 以鼠标为中心缩放 |
| `中键拖动` | 平移画布 |
| `S` | **保存并跳到下一张未标注的图** |
| `Ctrl+S` | 保存当前标定 |
| `Ctrl+Z` / `Ctrl+Y`（或 `Ctrl+Shift+Z`） | 撤销 / 重做 |
| `Ctrl+C` / `Ctrl+V` / `Delete` | 复制 / 粘贴 / 删除选中对象 |
| `PageUp` / `PageDown` | 上一张 / 下一张 |
| `Ctrl+0` / `Ctrl+9` | 1:1 / 适应窗口 |

> 切换样本或关闭程序时若有未保存的标定，会弹窗询问保存 / 放弃 / 取消。

### 5. 数据划分

在左侧图像池中多选图像（`Ctrl` / `Shift` / `Ctrl+A`），**右键**：

- 加入训练集 / 加入测试集 / 移出划分
- 设为 OK 图（无缺陷正例）/ 取消 OK 图标记
- 智能标注选中图像
- 打开所在文件夹 / 从工程中删除图片

图像池每行显示：`[划分] 状态 文件名 OK标记`，其中状态 `·` = 未标注、`预` = 预标注、`●` = 已完成。

### 6. 训练

**训练 → 开始训练**（`Ctrl+T`）。参数在左侧「训练 / 测试参数」中设置（可收起）。
训练监控窗口实时显示进度、损失 / 指标曲线与彩色日志，可随时「中止训练」。

**训练完成后会自动在测试集上评价**，并把逐图预测结果写入 `results/`。

### 7. 智能标注（预标注）

**训练 → 智能标注**（`Ctrl+Shift+A`）：用已训练模型对「当前图 / 选中图 / 全部未标注图」
自动预标注。预标注对象在画布上是**虚线**、在对象列表里带 **`[预]`** 标记，
人工复核后点「确认预标注」才转为正式标注。

> 预标注需要该模块已有模型；没有时会明确提示，而不是静默失败。

### 8. 结果验证与导出

- **显示类型**（底部）在「原图 / 标注 / 测试结果」之间切换，并调整掩码透明度；
- **评价指标**面板显示整体与逐类精确率 / 召回率 / F1 / mIoU，以及**漏检率 / 过检率**；
- **文件 → 导出模型**：把模型主文件与元数据导出到指定目录；
- **测试 → 模型测试**：载入任意模型与任意图像运行推理并可视化（可用来验证导出件）。

## 六、数据格式

### 工程目录

```
<工程根>/
├─ project.json                工程描述
├─ images/                     工程级图像池（按工程图片格式统一转码）
├─ thumbs/                     缩略图缓存
└─ modules/<moduleId>/
   ├─ module.json              模块描述（类型 / 类别 / 训练与测试参数）
   ├─ samples.json             每张图的 划分 + OK + 标注状态
   ├─ labels/                  标注（.json 为真源；分割另含派生 .png 掩码）
   ├─ models/                  训练产物 model.* + model.json 元数据
   ├─ results/                 metrics.json + <图名>.json（每图预测）
   └─ logs/
```

### `project.json`

```json
{ "format": "AqroTrain.Project", "version": 1, "name": "表面缺陷",
  "imageFormat": "png", "created": "2026-10-11T12:00:00",
  "modules": [ { "id": "m1", "name": "分割-划痕", "type": "segmentation", "order": 0 } ] }
```

### `modules/<id>/module.json`

```json
{ "id": "m1", "name": "分割-划痕", "type": "segmentation", "order": 0,
  "hasBackground": true,
  "classes": [ {"name":"背景","color":"#000000"}, {"name":"划痕","color":"#E6194B"} ],
  "train": { "backend":"opencv", "model":"resnet18", "epochs":50, "batchSize":8,
             "learningRate":0.001, "inputWidth":224, "inputHeight":224, "useGpu":false },
  "test":  { "scoreThreshold":0.5, "nmsThreshold":0.45, "iouThreshold":0.5, "minArea":16 } }
```

### `modules/<id>/samples.json`

```json
{ "format": "AqroTrain.Samples", "version": 1,
  "samples": { "img_0001.png": { "split": "train", "ok": false, "state": "done" } } }
```

`split ∈ {none, train, test}`；`state ∈ {none, pre, done}`。

### 类别索引约定（全局统一）

| 模块类型 | 约定 |
| --- | --- |
| **图像分类** | `classes` 只含真实类别，索引 `0..N-1`，**无背景类** |
| **目标检测** | 索引 `0` 固定为「背景」，目标类别从 `1` 开始 |
| **图像分割** | 同上；掩码像素值 = `classes` 索引，`0` 为背景 |

### 标注文件

| 模块类型 | 文件 | 内容 |
| --- | --- | --- |
| 分类 | `labels/<同名>.json` | `{"classId":2,"state":"done"}` |
| 检测 | `labels/<同名>.json` | 对象列表：`rect` / `polygon`，像素坐标 |
| 分割 | `labels/<同名>.json` + `labels/<同名>.png` | `.json` 是对象列表（真源）；`.png` 是 `CV_8UC1` 掩码（**派生物**，像素值=类别索引） |

**一致性规则**：`.json` 是唯一真源，`.png` 每次保存时由对象列表重新光栅化；
若只有 `.png`（外部导入 / 旧数据），用连通域分析反推成等价对象并标 `derived: true`，同样可编辑。

### 模型文件

- 主模型：`models/model.clsmodel` / `model.detmodel` / `model.segmodel`
- 元数据：`models/model.xxx.json`（记录 `task` / `backend` / `model` / 输入尺寸 /
  `classes` / 训练时间 / 指标摘要）。「模型测试」与「智能标注」依赖它识别任务与类别。

## 七、自检模式

程序内置四个无人值守模式，用于回归验证与环境排查：

```powershell
$exe = '<仓库路径>\build\x64\Release\AqroTrain.exe'

# 1) 界面冒烟测试：构建主窗口、（可选）打开工程、截图后自动退出（退出码 0 表示成功）
& $exe --selftest D:\tmp\shot.png [工程目录]

# 2) 端到端自检：为三类模块生成合成数据集，各跑一次真实训练与评价，
#    并验证模型导出后能被重新加载推理。退出码 0 表示全部通过。
& $exe --autotrain D:\tmp\autotrain D:\tmp\report.txt

# 3) 标注交互自检：直接向画布 viewport 派发鼠标事件，验证
#    画笔 / 橡皮 / 多边形 / 顶点编辑 / 撤销重做 / 固定尺寸框 / 背景类拦截，
#    并断言「对象列表光栅化掩码 == 画布掩码」逐像素相等。
& $exe --anno-selftest D:\tmp\anno_report.txt

# 4) 目录创建诊断：排查「无法创建工程 / 无法创建目录」
& $exe --diag-mkdir "F:\some\path\newproject" D:\tmp\mkdir_diag.txt
```

`--autotrain` 还支持一个只影响自检的环境变量，用来做「阈值 - 指标」曲线：

```powershell
$env:AQROTRAIN_AUTOTRAIN_SCORE = '0.85'   # 覆盖各模块的置信度阈值，再跑 --autotrain
Remove-Item Env:\AQROTRAIN_AUTOTRAIN_SCORE
```

**遇到「无法创建目录」时**用第 4 条排查。诊断会逐层报告路径状态，
**逐个 API 报告尝试结果与真实 Win32 错误码**，并做一次「写文件探测」，
失败时给出精确原因，例如：

```
无法创建目录：D:\datasets\1\1

失败层级：D:\datasets\1\1
原因：本进程无法往上级目录写入（探测：无法在 D:\datasets\1 中新建文件（拒绝访问。））
最后一个 API 的返回：CreateDirectoryW → 拒绝访问（ERROR_ACCESS_DENIED）：被 ACL 或安全软件/组策略拦截
上级目录：D:\datasets\1
　（存在=是，是目录=是，可写=是，权限=rwx，写文件探测=失败）
各 API 尝试结果：
　· Win32 CreateDirectoryW：失败（错误码 5：拒绝访问）
　· Qt QDir::mkdir：失败（错误码 5：拒绝访问）
　· CRT _wmkdir：失败
　· 外壳 SHCreateDirectoryExW：失败（错误码 5：拒绝访问）
　· Qt QDir::mkpath：失败（错误码 5：拒绝访问）
```

### 目录创建是怎么做的（以及为什么不是一句 `mkpath`）

`ProjectManager::ensureDir()` 从盘符起**逐层创建**，并遵守以下约定：

- **不使用 `QDir::mkpath` 作为主路径**：它一次性递归创建，任意一层判定异常就整体失败，
  且无法知道是哪一层、为什么失败。
- **单层创建会依次尝试 5 种 API**：`CreateDirectoryW`（含长路径 `\\?\` 前缀）、
  `QDir::mkdir`、CRT `_wmkdir`、外壳 `SHCreateDirectoryExW`、`QDir::mkpath`。
  任一成功即算成功，并把**每个策略的真实结果与 Win32 错误码**记下来。
  这样既是兜底，也让失败原因可诊断。
- **支持超过 `MAX_PATH`(260) 的长路径**：路径达到 250 字符起自动加 `\\?\` 前缀。
  实测可创建 **377 字符**的目录。而且**建得出就要删得掉**：
  `ProjectManager::removeDirRecursive()` 用 `FindFirstFileW / DeleteFileW / RemoveDirectoryW`
  自己递归并全程带长路径前缀 —— 因为 `QDir::removeRecursively()`、`rmdir`、资源管理器
  **都删不掉 >MAX_PATH 的目录**，只用它们会留下永远清不掉的垃圾。删除模块、重建工作目录
  也走这个函数。
- **目录已存在视为成功**（含并发创建的竞态），同名**文件**占位则明确报错。
- **不做不可靠的前置判断**：Windows 下 `QFileInfo::isWritable()` / 只读属性 /
  `permissions()` 的结论实测会互相矛盾（同一进程内对同一目录先返回 `r-x`、后返回 `rwx`）。
  真正可靠的判据是**探测**：`probeWritable()` 会往目标目录里真的写一个临时文件再删掉。
- **自检报告写不出去时不再静默失败**：按「指定路径 → 工作目录 → 程序目录」回退，
  并把实际写入位置打印到 stderr。原先报告写失败会让使用者拿不到报告、退出码却仍是成功。

### 权限受限时不会把你堵死

新建工程失败时，程序不会只弹一句报错，而是给出三条能走下去的路：

| 选项 | 说明 |
| --- | --- |
| **直接用这个目录当工程目录** | 目录已存在，**完全不需要任何「创建目录」权限**；只要它是空目录即可（默认按钮） |
| 换一个文件夹… | 另选一个已存在的空目录 |
| 建在上次的位置 | 改用上次成功使用的工程父目录 |
| 重试 | 例如刚在安全软件里点了「允许」之后 |

> 这一条很重要：**很多环境**（第三方安全软件的文件夹保护、组策略、
> 受限的进程令牌）会拒绝创建目录，但**不会**拒绝写入一个已存在的目录。
> 此时「直接使用已存在目录」是唯一能走通的路，程序必须提供它。

### 怎么区分「真的不可写」和「被安全软件拦了」

看诊断里的**写文件探测**：

| 情况 | 含义 | 处理 |
| --- | --- | --- |
| 写文件**成功**，但建目录失败 | 不是普通权限问题，是安全软件/策略**专门拦了目录创建** | 加入信任区；或改用「直接使用已存在的目录」 |
| 写文件**也失败**（`ERROR_ACCESS_DENIED`） | 本进程确实被拒绝写入该位置 | 换位置 / 以管理员运行 / 检查进程是否运行在受限上下文里 |

> **实测提醒**：如果一个进程运行在**受限的启动上下文**里（沙箱、受限令牌、
> 被安全软件降权的父进程），它可能在整个盘上只能写某几个目录，
> 而对其它目录一律返回 `ERROR_ACCESS_DENIED` —— 此时 ACL、只读属性、
> 甚至「用其它工具去写同一个目录」都显示正常。
> **判断方法**：用不同方式启动同一个 exe 对比。本机实测过：同一个
> `AqroTrain.exe`、同一个路径 `D:\datasets\1\1`，从受限上下文的 shell 启动会失败，
> 而从系统服务（WMI）启动则**一次成功** —— 说明问题在启动上下文，不在路径也不在代码。

### 已知局限：OpenCV 轻量后端的检测精度（实测）

轻量后端的检测是「多尺度滑窗 + 图块分类 + NMS」的**简化实现**，不是真正的检测网络。
实测精确率远低于可用水平，而召回率随配置在 25% ~ 100% 间大幅波动：

| 配置 | 精确率 | 召回率 | F1 | 漏检率 |
| --- | --- | --- | --- | --- |
| 仅用标注框作正样本 | 50.0% | 25.0% | 0.333 | 50% |
| 正样本抖动增广（当前默认） | **8.7%** | **100%** | 0.160 | **0%** |
| 正样本抖动 + 置信度阈值 0.85 | 12.7% | 100% | 0.225 | 0% |

选择「抖动增广」作为默认，是因为缺陷检测里**漏检比过检代价大得多**
（AIDI 自己也把漏检率/过检率作为核心指标）。但精确率确实很差，原因有二：

1. 图块特征是把图块缩放后**拉平成像素向量**，对窗口位置敏感；
   检测阶段能拿到的正样本只有「标注框」这一种对齐方式，模型只认识训练时的对齐。
   （试过换成「灰度直方图 + 色相直方图」这类平移不变描述子，
   实测反而更差：召回率 37.5% → 12.5%、精确率 25% → 0.9%，故保留基线实现。）
2. 多尺度 × 多长宽比滑窗会产生大量部分重叠的候选框。
   已加入**包含抑制**（低分框 80% 以上面积落在高分框内即判为重复），
   实测把精确率从 0.9% 提升到 50%（非抖动配置下），但仍不足以解决根本问题。
3. 置信度是**森林投票占比**而不是标定过的概率，所以提高阈值对精确率的改善很有限
   （0.50 → 0.85 只把精确率从 8.7% 提到 12.7%）。

**结论：请把轻量后端的检测当作跑通流程的占位实现。**
需要可用的检测精度应启用 LibTorch 后端（见第三节），或在 AIDI 上使用真正的检测模型训练。
分类与分割不受此影响。

### 分类精度与缺陷面积的关系（实测）

同一套合成数据，只改缺陷块大小：

| 缺陷占图面积 | 测试集精确率 / 召回率 |
| --- | --- |
| 约 6%（40~60 px / 192²） | 50% / 50%（≈随机） |
| 约 25%~40%（90~120 px / 192²） | **100% / 100%** |

轻量后端的分类特征是**全局** HSV 直方图 + 8×8 缩略图，缺陷很小时信号被背景稀释，
随机森林学不到。这也是自检刻意使用较大缺陷块的原因（自检验证的是数据流通路，
不是去赌算法在小目标上的运气）。**实际项目中的小缺陷分类请用 LibTorch 后端。**

## 十、二次开发提示

### 架构分层

```
ui/         只与 ProjectManager 交互，不直接碰文件
  ↓
project/    ProjectManager 是数据层唯一门面（工程/模块/图像池/样本状态/标注/训练视图）
annotate/   AnnoObject 是标注真源；ImageCanvas 负责交互与撤销
train/      ITrainer 是后端接口；Evaluator 负责评价
core/       Types / ImageIO / JsonStore / Metrics —— 无重依赖
```

### 关键约定与踩过的坑

- **分割掩码是派生物**：真源是对象列表。任何直接改掩码而不改对象的写法都会让两者不一致，
  自检里的「对象光栅化掩码 == 画布掩码」断言就是为了守住这条约定。
- **画笔：一次手势只产生一个对象；在已画过的地方再画不再新增顶点**（点数 ≠ 鼠标移动次数）。
  机制是「**按本笔画已记录点的邻域跳过** + RDP 简化」，判据选在**本笔画自己的采样轨迹**上：
  - `strokeAlreadyCovers()`：新采样点若落在本笔画已记录点的**笔尖半径邻域**内就跳过。
    依据是笔尖是圆的 —— 相邻两笔圆心距 ≤ 半径 时覆盖区域基本重合
    （两个半径 R、圆心距 R 的圆盘，并集在中点收窄 13%；半径 12px 时不到 1.6px，肉眼不可见）。
    空间索引是格子边长 = 半径的 `QHash`，只查 3×3 邻域再逐个比真实距离。
  - `simplifyCurrentStroke()`：每 64 个采样点、以及抬手时，做一次 **RDP 简化**
    （`anno::simplifyPolyline`，容差 `clamp(半径*0.1, 1px, 3px)`）。距离用「点到**线段**」，
    因此折返也能正确折叠。
  - **尾部补齐**：跳过规则下最后一个采样点可能离抬手位置还差将近一个笔尖半径，
    收尾时把抬手点补上（实测不补会让 100px 拖拽的跨度少 9px）。
  - 撤销仍然**一次手势一步**：只在第一次真正写入时才 `pushUndo()`；
    在已画区域空点、或橡皮擦划过空白，既不产生对象也不留下撤销步骤。
  - 实测：5px 细笔在同一处反复涂 10 趟 → **24 → 24 个点（不再增长）**；
    0.5px 抖动的 200 次移动 → 1 个点；10px 笔沿圆周涂一圈 → **17 个点**、
    1 个连通域、环心为空、环带面积 2712（理论 2513）。

  ⚠ **两个错误做法都实测踩过，不要再犯**：
  - 拿「掩码像素值已经等于本类别」当「已画过」的判据：笔尖半径内的像素刚被本笔自己涂过，
    于是每一段都被当成多余而跳过，笔画退化成「每隔约一个笔尖直径一个圆点」
    （一笔变成 140 个「1 顶点」对象）。**判据必须是采样轨迹，不能是掩码当前值。**
  - 为了「省点」而在拖动中**另起新对象（分段）**：来回涂抹时每折返一次就多一个对象，
    对象数随鼠标动线增长（实测 11 个对象）。**对象数量不该由动线决定。**
  - 另外：只用最小间距（`半径*0.25`）+ RDP 是不够的。细笔（5px）时最小间距只有 1px、
    容差被夹到 1px，密涂同一处仍会涨到 557 个顶点（这也是实测）。

  自检用这些断言把这些退化钉死：**对象数 == 1**（来回涂抹、圆周涂抹、连续拖动）、
  **前景连通域 == 1**、**掩码跨度覆盖整个拖拽范围**、**同一处 10 趟点数不增**、
  **环带面积在理论值 75%~130% 内且环心为空**；并单测 RDP（折返折叠、锯齿保留、离群点保留）。
  `--anno-selftest` 还会把连续拖动的结果渲染成
  `<输出目录>/brush_continuity.png`，便于人眼直接确认平不平滑。

  **已知取舍**：若使用者在同一次手势里穿过已画区域、再在较远处重新落笔，
  两点之间会被折线连成一条弦线。常见场景（在同一片区域涂实）下这条弦落在已涂区域内、
  对掩码无影响；只有「非凸形状 + 跨凹陷重落笔」才可能多涂一块，此时松开重画一笔即可。
  要彻底消除需要给 `AnnoObject` 增加「一条笔画含多个子路径」的表达（尚未实现）。
- **掩码增量刷新**：编辑对象时只对「旧包围盒 ∪ 新包围盒」的 ROI 重光栅化
  （`anno::rasterizeRegion`），不要整幅重算，否则大图上会明显卡顿。
- **撤销统一为对象列表快照**：对象数通常 < 200，内存可控，且不会出现
  「掩码与对象不一致」的中间态。栈深 50。
- **`QGraphicsView` 的事件由 viewport 接收后再转发**：写测试或模拟事件时必须发给
  `canvas->viewport()`，发给自己收不到。
- **场景坐标 == 图像像素坐标**：缩放平移交给视图变换，不要手写
  `imageToWidget` / `widgetToImage`。
- **图元的 `boundingRect` 会随视图缩放变化**（手柄按屏幕恒定尺寸换算），
  因此缩放后要 `m_scene->invalidate()`，否则可能留下重绘残影。
- **`cv::LUT` 要求查找表通道数等于输入通道数或为 1**：单通道索引图配三通道表会抛异常，
  必须对 B / G / R 分别查表再 `merge`。
- **JSON 一律用 Qt `QJsonDocument`**，不要用 OpenCV `FileStorage` 落临时文件
  （受限环境与中文路径下曾出现 `Can't open file ... in write mode`）。
- **`cv::ml::RTrees::getVotes` 的输出矩阵是 `(nsamples+1) × nclasses`**，
  **票数从第 1 行开始**、第 0 行是类别标签，读错会导致置信度恒为 0。
- **`ClassPanel` 只在用户主动点选时发 `classPicked`**；程序化刷新发
  `currentClassChanged`。分类模块的「点一下即标定」依赖这个区分，
  否则刷新面板会把当前图误标定。
- **数字键类快捷方式放在画布而不是全局 `QAction`**：全局数字快捷键会抢走参数输入框的数字输入。
- **目录创建用逐层 `QDir::mkdir`** 而不是 `QDir::mkpath`：`mkpath` 一次性递归创建，
  任意一层判定异常就整体失败且无法定位是哪一层、为什么失败。

### 新增源文件时必须手动加入工程（重要）

`AqroTrain.vcxproj` 使用**显式文件列表**，而不是 `src\**\*.cpp` 这类通配符。这是刻意的：

- VS 的 C++ 项目系统**不支持 vcxproj 中的通配符**，会给出
  「VC 项目不支持项目定义中使用的通配符」警告，并可能导致项目加载异常或性能下降；
- 带 `Q_OBJECT` 的头文件**只能**出现在 `<QtMoc>` 项中，不能同时出现在 `<ClInclude>` 中，
  否则 VS 报「筛选器 "" 下已存在项目」而**整个项目加载失败**。

因此新增文件时请同步修改两处：

1. `AqroTrain.vcxproj` —— 按类型加入 `<ClCompile>` / `<ClInclude>` / `<QtMoc>`；
2. `AqroTrain.vcxproj.filters` —— 加入同名条目并指定所属筛选器（目录分组）。

> 判断标准：头文件里写了 `Q_OBJECT` 就放 `<QtMoc>`，否则放 `<ClInclude>`，**两者互斥**。
